**前置条件**: Phase 2 已验收通过  
**目标**: 在现有多对象分析、传感器、覆盖、环境与 AI 基础上，补齐高精度传播、姿态基础与链路分析能力，使 KST 从“基础分析工具”提升到“可支撑工程级轨道与任务分析”的水平。

## 1. Phase 3 总体目标

Phase 3 结束后，用户应能够：

- 使用包含主要摄动力的数值积分传播器进行轨道预报（至少支持 J2 + 大气阻力）
- 对卫星进行基础姿态建模，并与传感器指向联动
- 进行基础通信/雷达链路预算分析
- 在三维中可视化姿态、传感器指向与链路状态
- 支持从公开数据源（如 Space-Track）导入或更新 TLE
- 获得比 Phase 2 更可靠的工程分析结果

## 3. 详细功能要求（必须严格执行）

### 3.1 数值积分传播器（P0）

**要求**：
- 实现至少一种自适应或固定步长数值积分器（推荐 Dormand-Prince 或 Runge-Kutta）。
- 力模型至少包含：
  - 中心引力
  - J2 摄动
  - 大气阻力（可复用 Phase 2 的 NRLMSISE-00 密度）
- 支持用户配置积分步长、是否启用各项摄动。
- 输出与 SGP4 相同格式的状态序列，便于前端复用。
- 必须在 Rust 后端实现。

**参考要求（必须评估）**：
- 优先参考 `ssmichael1/satkit` 与 `duncaneddy/brahe` 的积分器与力模型结构。
- 如不采用上述库的核心算法，必须在设计说明中给出理由。

**禁止**：
- 禁止仅用解析公式近似代替数值积分。
- 禁止积分器无步长控制或无基本稳定性保护。

### 3.2 传播器对比与切换（P0）

**要求**：
- 场景中卫星可选择传播器类型（SGP4 / 数值积分）。
- 支持对同一时间窗口同时计算两种传播器结果并对比（位置差、速度差统计）。
- 对比结果可在界面中查看并导出。
- SGP4 实现继续使用或评估升级到更成熟的 crate（如 `neuromorphicsystems/sgp4`）。

### 3.3 基础姿态模型（P0）

**要求**：
- 支持以下姿态模式（至少实现 3 种）：
  - Nadir（对地）
  - Sun-pointing（对日）
  - Fixed（固定惯性或轨道系姿态）
- 姿态计算基于当前轨道状态，输出本体坐标系到地固系/惯性系的旋转。
- 姿态结果可被传感器指向模块调用。

**禁止**：
- 禁止姿态计算只在前端完成。

### 3.4 姿态与传感器联动（P0）

**要求**：
- 传感器指向模式中增加“基于卫星姿态”选项。
- 当卫星姿态变化时，传感器视场在三维中相应旋转。
- Access 计算中的传感器约束必须使用真实姿态结果。
- 传感器可视化效果不得明显差于 `kaktus40/cesium-sensors` 的基础实现。

### 3.5 基础链路预算（P0）

**要求**：
- 支持发射机-接收机基础模型（频率、功率、天线增益、系统噪声温度等）。
- 计算自由空间路径损耗。
- 支持简单大气衰减模型（可配置或使用经验公式）。
- 输出：接收功率、载噪比、链路余量。
- 计算结果可关联到 Access 窗口。

**禁止**：
- 禁止只做距离计算而不做功率与损耗计算。

### 3.6 公开数据源接入（P1）

**要求**：
- 支持从 Space-Track 获取 TLE / OMM 并导入场景。
- 提供手动刷新或定时更新接口（至少支持手动）。
- 导入后可直接用于 SGP4 传播。
- 需处理 Space-Track 的认证与访问限制（账号注册、速率限制等）。

### 3.7 可视化要求（P1）

- 卫星姿态：至少显示本体坐标轴或简单模型方向。
- 链路：在三维中以不同颜色或线宽表示链路余量状态。
- 数值积分与 SGP4 轨道可用不同样式区分。
- 整体视觉风格继续参考 `Flowm/satvis` 与现有 Safety Platform 风格，不得明显退化。

## 5. 技术与架构约束

1. **计算位置**：所有新增传播、姿态、链路计算必须在 Rust 后端完成。
2. **性能**：
   - 数值积分任务必须走异步任务队列。
   - 提供合理的步长与时间范围限制，防止过长计算阻塞。
3. **数据模型**：
   - 卫星对象增加 `propagator_type`、`attitude_mode` 等字段。
   - 新增链路相关对象或在地面站/卫星上扩展通信参数。
4. **开源评估记录**：对第 4 节列出的高优先级项目，必须在代码注释或文档中说明参考情况。
5. **视觉一致性**：新增可视化元素风格必须与现有深色 Cesium 场景保持一致。

## 6. 开发顺序（强制建议）

1. 数据模型扩展（传播器类型、姿态模式、链路参数）
2. 数值积分器核心 + J2 + 大气阻力（参考 satkit/brahe）
3. 传播器切换与对比功能
4. 基础姿态模型
5. 姿态与传感器联动 + 三维可视化（参考 cesium-sensors）
6. 基础链路预算计算
7. 链路可视化与 Access 关联
8. Space-Track 数据源接入
9. 覆盖分析增强（多卫星）
10. 整体联调、性能优化与开源评估说明

## 8. 明确禁止事项

- 禁止用解析二体或简单公式冒充数值积分器。
- 禁止姿态或链路计算放在前端。
- 禁止只实现数据模型而不做三维可视化与实际计算联动。
- 禁止因新增传播器导致原有 SGP4 与 Access 功能异常。
- 禁止无步长/时间限制的长时间数值积分任务直接阻塞请求。
- 禁止对第 4 节高优先级推荐项目完全不评估就自行实现。
- 禁止擅自缩减“必须”项后声称 Phase 3 完成。
