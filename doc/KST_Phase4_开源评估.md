# KST Phase 4 开源项目与数据源评估

**版本**：v1.0  
**日期**：2026-11-26  
**依据**：`doc/KST_Phase4_开发计划书_v1.0.md` 第 4 节（强制评估）

本文档记录 Phase 4 推荐开源项目与数据源的评估结论、采用方式与不采用理由。结论与 `backend/src/constellation.rs`、`backend/src/link.rs`、`backend/src/radar.rs`、`backend/src/report.rs`、`backend/src/rate_limit.rs`、`frontend/src/components/*.vue`、`frontend/src/composables/useCesiumViewer.ts` 中的实现保持一致。

## 2. 逐项评估

### 2.1 Walker 构型公开文献与 AGI/STK 文档（参考）

- **用途**：Walker Delta / Walker Star 星座参数化与轨道面分布。
- **评估**：Walker 构型通常以 `T/P/F` 描述：总卫星数 T、轨道面数 P、相位因子 F；同面卫星升交点赤经相同、平近点角均布，相邻面之间按 `F × 360°/T` 错开相位。Walker Delta 的升交点覆盖 360°，Walker Star 使用 180° 的极轨/近极轨分布。
- **结论**：**参考不引入代码**。原因：
  1. 公开文献只提供参数关系，没有可直接复用的、与当前数据模型匹配的 Rust 实现；
  2. 生成器需要与项目 TLE 校验、颜色分配、场景对象 ID 规则深度结合，自行实现更可控；
  3. 逻辑规模小（数十行），引入第三方星座库会带来不必要的依赖。
- **落地**：`backend/src/constellation.rs` 实现 `T/P/F` 校验、升交点均布、面内相位均布与 `F` 相位偏移；生成固定列宽、带校验和的 TLE，并使用 `sgp4::Elements::from_tle` 逐星校验，确保生成后可直接参与传播与 Access。

### 2.2 街道式覆盖（Streets of Coverage）公开资料（参考）

- **用途**：街道式星座构型生成。
- **评估**：街道式覆盖通常由多个近极轨“街道”组成，同一条街道内卫星等间隔运行，相邻街道的卫星相位错开，以缩短中低纬区域的覆盖间隙。
- **结论**：**参考不引入代码**，理由同 2.1。
- **落地**：`backend/src/constellation.rs` 将“街道”映射为轨道面，要求 `街道数 × 每街卫星数 = 卫星总数`；升交点覆盖 180°，相邻街道按半周期错开相位，生成结果与 Walker 星座共用同一套 TLE 校验与场景对象结构。

### 2.3 公开链路预算教材实现与 ITU-R P.676（参考）

- **用途**：自由空间损耗、天线方向图、大气衰减与链路余量。
- **评估**：
  - 链路预算核心公式（EIRP、FSL、G/T、C/N0、Eb/N0）在教材与公开实现中高度一致；
  - ITU-R P.676 给出大气气体衰减随频率与仰角的变化，工程上常用天顶衰减 + `1/sin(仰角)` 近似；
  - 开源实现多绑定具体无线电平台或 Python 生态，直接移植会引入额外依赖。
- **结论**：**参考不引入代码**，在既有 `link.rs` 上扩展。
- **落地**：
  - 天线方向图支持 `omni` 与 `cosine`（`10·n·log10(cos θ)`，限制在 [-60, 0] dB）；
  - 大气模型支持 `none`、`simple`（天顶 0.05 dB、按仰角放大）与 `itu`（按频率查表或使用用户输入的天顶衰减）；
  - 输出逐点 `curve`（时间、仰角、距离、C/N0、余量），前端绘制余量曲线；
  - 新增同频干扰分析：对目标链路与多个干扰源逐点计算 C/I，按线性功率求和，输出最小/平均 C/I 与低于门限比例。

### 2.4 基础雷达方程公开实现（参考）

- **用途**：单站雷达最大探测距离与 SNR 估算。
- **评估**：雷达方程 `R_max = [Pt·Gt·Gr·λ²·σ / ((4π)³·L·k·T0·B·F·SNR_min)]^(1/4)` 为标准公式；公开实现多面向相控阵或信号处理链，超出本期“基础雷达分析”的范围。
- **结论**：**参考不引入代码**。
- **落地**：`backend/src/radar.rs` 实现：
  - 由雷达方程计算最大探测距离；
  - 逐采样点计算斜距与 SNR，并叠加 `10·log10(N)` 脉冲积累增益；
  - 复用 `orbit::compute_access` 的可见窗口几何，输出窗口级最大 SNR、可探测时长与 CSV；
  - 结果可在三维中以探测球、可探测弧段和实时波束连线展示。

### 2.5 Apache ECharts（本期不采用）

- **用途**：报告图表（时间线、余量曲线、覆盖热力）。
- **评估**：ECharts 功能完整、交互丰富，但报告需要在后端生成并支持脱离前端运行时的 Markdown/HTML 导出。
- **结论**：**本期不采用**。原因：
  1. 报告要求“后端完成结构化数据、前端负责渲染与导出”，若依赖 ECharts 运行时，HTML 报告将无法独立打开；
  2. 图表类型固定且简单（时间线、折线、覆盖网格），内联 SVG 体积小、零依赖、可打印；
  3. 引入 ECharts 会增加前端包体与报告导出链路复杂度。
- **落地**：`backend/src/report.rs` 生成自包含 HTML（内联 CSS + SVG），包含 Access 时间线、覆盖热力图、链路余量曲线与雷达 SNR 曲线；Markdown 版本保留表格与统计。前端提供 HTML/Markdown 下载与浏览器打印为 PDF。
- **后续**：若需要交互式图表，可在前端报告预览中单独评估 ECharts，不影响后端报告格式。

### 2.6 Axum 0.8 Router / Tower 中间件（采用）

- **用途**：自动化 API、异步任务与限流。
- **评估**：项目已使用 Axum 0.8 与 SQLx，新增路由与中间件成本最低，且能复用既有 `AuthUser` 鉴权。
- **结论**：**继续采用**。
- **落地**：
  - `POST /api/v1/constellations/generate` 生成星座（需鉴权）；
  - `POST /api/v1/jobs` 扩展 `constellation_analysis`、`radar`、`report`、`interference` 四类异步任务；
  - `GET /api/v1/jobs/{id}/report?format=html|markdown` 下载报告；
  - `backend/src/rate_limit.rs` 基于 Authorization 头的固定窗口限流（240 次 / 60 秒 / 键），对计算类路由生效，超限返回 429。

### 2.7 Cesium 官方 Entity / Polyline / Ellipsoid 示例（采用）

- **用途**：星座、链路与雷达三维可视化。
- **评估**：项目已使用 Cesium 1.147 与原生 Entity API；官方示例覆盖折线、发光材质、椭球与虚线材质。
- **结论**：**采用官方 API**，不引入额外封装。
- **落地**：
  - 星座卫星按轨道面/按星着色，沿用既有深色配色；
  - 链路按窗口最小余量着色，并按余量调整线宽；
  - 雷达使用半透明椭球表示最大探测范围、绿色发光弧段表示可探测窗口、虚线连线表示实时波束，颜色随是否可探测切换。

### 2.8 kaktus40/cesium-sensors（参考）

- **用途**：传感器视场可视化参考。
- **评估**：与 Phase 3 结论一致，其示例与当前深色主题和 Entity 结构需要较多改造。
- **结论**：**参考不引入**。Phase 4 的雷达可视化直接使用 Cesium 原生椭球与折线，避免新增依赖。

### 2.9 CZML 规范（本期不采用）

- **用途**：与外部工具（STK 等）交换场景。
- **评估**：CZML 适合 Cesium 时间动态场景交换，但需要完整的对象映射、时间采样与外部工具兼容性验证。
- **结论**：**本期不采用**，列为 P2。当前 API 已提供 JSON 场景与 CSV/HTML/Markdown 导出，满足自动化分析需求。

## 4. 架构约束落实情况

- **计算位置**：星座生成、批量覆盖/Access、链路预算、雷达、干扰与报告全部在 Rust 后端完成；前端仅负责参数输入、结果展示与三维渲染。
- **异步任务**：`constellation_analysis`、`radar`、`report`、`interference` 均通过 `computation_jobs` 异步执行，使用 `spawn_blocking` 避免阻塞请求线程。
- **计算保护**：
  - 星座批量分析限制网格点 1500、卫星 48、组合数 2×10⁸，超限返回明确提示；
  - 报告限制卫星 10、地面站 5、Access 对 8；
  - 干扰分析限制干扰源 20 个；
  - 计算类路由统一限流 240 次/分钟。
- **数据模型**：场景新增 `constellations`；卫星新增 `link_options` 与 `radar_options`；链路参数扩展方向图与大气模型。
- **视觉一致性**：新增星座、链路、雷达元素沿用既有 `--kst-*` 深色配色、发光/虚线材质与面板样式；右侧标签改为两行排列，避免新增标签被横向裁切。
