# KST Phase 2 开发计划书（严格实施版）

**版本**: v1.0  
**日期**: 2026-11-25  
**前置条件**: Phase 1 已验收通过  
**目标**: 在 Phase 1 多对象基础分析能力之上，提升分析深度、引入环境与传感器能力，并落地可用的 AI 辅助功能。  
**强制原则**:  
- 不得因功能增加而降低 Phase 1 已达成的视觉与计算标准。  
- 所有“必须”项未完成不得宣称 Phase 2 完成。  
- 参考路径与推荐库为硬性约束，不得无理由自行简化或替换。

---

## 1. Phase 2 总体目标

交付一个**具备中等分析深度**的空间任务工具，用户能够：

- 进行多约束 Access 分析（含简单传感器/遮挡）
- 查看环境模型对轨道的基础影响
- 进行基础覆盖分析
- 使用 AI 辅助完成场景生成、结果解读与报告生成
- 在三维中清晰展示传感器锥、覆盖区域、Access 弧段等

Phase 2 结束后，产品应明显超越“基础传播 + 简单 Access”，接近可用的专业分析工具雏形。

## 3. 详细功能要求（必须严格执行）

### 3.1 多约束 Access（P0）

**要求**：
- 在 Phase 1 仰角约束基础上，增加：
  - 方位角范围约束（例如仅南向）
  - 地球遮挡判断（使用几何方法）
  - 简单传感器视场约束（卫星传感器是否指向地面站）
- 约束可组合，结果窗口需标注满足的约束类型。
- 计算仍必须在 Rust 后端完成，优先复用 `stkcraft-geocalc` 的 Geometry Finder 能力。

**禁止**：
- 禁止仅在前端做约束过滤。
- 禁止用固定步长粗采样代替边界插值。

### 3.2 基础传感器模型与可视化（P0）

**要求**：
- 支持至少两种传感器：圆锥视场、矩形视场。
- 传感器可绑定到卫星，设置指向模式（固定、对地、对目标等至少两种）。
- 三维中必须可视化传感器锥/视场边界。
- 参考实现：`kaktus40/cesium-sensors` 或等效方案，但最终渲染必须与现有 Cesium 架构兼容。

**验收**：
- 能在三维中看到传感器锥随卫星运动。
- 传感器约束能影响 Access 计算结果。

### 3.3 环境模型接入（P0）

**要求**：
- 接入 `stkcraft-spaceenv` 中的至少一个大气密度模型。
- 在 SGP4 结果基础上，提供“考虑大气阻力的简易修正”或对比展示（不要求完整 HPOP）。
- 报告中必须能看到环境参数对结果的影响说明。

**禁止**：
- 禁止只写接口不实际调用。
- 禁止用前端模拟环境效果。

### 3.4 基础覆盖分析（P0）

**要求**：
- 支持对指定区域生成简单经纬网格。
- 计算每个网格点对选定卫星的可见时间或覆盖次数。
- 输出统计报告（总覆盖率、平均覆盖时长等）。
- 结果可导出 CSV。

**可视化（P1）**：
- 在三维地球上以颜色或透明度显示覆盖强度。

### 3.5 AI 功能（P0 / P1）

**必须实现**：
1. **结果解读**（P0）：输入 Access 或覆盖报告，输出结构化中文摘要。
2. **参数推荐**（P1）：用户描述任务目标（例如“每天至少 3 次过境北京”），推荐轨道高度/倾角或传感器参数。
3. **报告生成**（P1）：基于计算结果生成可读性强的分析报告。

**实现要求**：
- 后端统一 `AIAdapter`，调用兼容 OpenAI 协议的云端 LLM。
- 敏感原始轨迹数据不得直接发送给 LLM，只发送摘要或用户确认的内容。
- AI 功能必须可关闭，关闭后核心计算不受影响。
- 提供至少 3 个预设 Prompt 模板。

**禁止**：
- 禁止把 AI 做成纯前端调用而无后端记录与权限控制。
- 禁止 AI 功能阻塞主流程。

## 4. 技术与架构约束

1. **计算位置**：所有新增几何、覆盖、传感器约束计算必须在 Rust 后端完成。
2. **视觉一致性**：新增三维元素（传感器锥、覆盖网格）风格必须与 Phase 1 保持一致，不得突兀。
3. **性能**：
   - 覆盖网格计算必须支持异步任务。
   - 单次覆盖任务网格点数建议限制（例如 ≤ 5000），并给出明确提示。
4. **数据模型扩展**：
   - 场景 JSONB 中增加 `sensors` 数组。
   - 新增 `coverage_jobs` 或复用 `computation_jobs` 并扩展 `kind`。
5. **推荐参考库**（优先评估，不得无理由忽略）：
   - 传感器可视化：`kaktus40/cesium-sensors`
   - 更高精度传播研究：`ssmichael1/satkit`、`duncaneddy/brahe`
   - AI 相关：`esa/dSGP4`（仅作探索参考）

---

## 5. 开发顺序（强制建议）

1. 数据模型扩展（传感器、覆盖任务）
2. 多约束 Access + 传感器模型（后端）
3. 传感器三维可视化
4. 环境模型接入与对比展示
5. 基础覆盖计算（后端异步）
6. 覆盖可视化
7. AI 结果解读
8. AI 参数推荐与报告生成
9. 整体联调与性能优化

---

## 6. 验收标准（全部满足方可通过）

- [ ] 可创建带传感器的卫星，并在三维中看到视场锥。
- [ ] Access 计算支持仰角 + 方位角 + 传感器约束的组合。
- [ ] 环境模型有实际调用，并能在界面或报告中体现影响。
- [ ] 可对指定区域进行网格覆盖计算，并导出结果。
- [ ] 覆盖结果可在三维中可视化。
- [ ] AI 可对 Access/覆盖结果生成中文解读。
- [ ] AI 可进行基础参数推荐。
- [ ] AI 可生成分析报告。
- [ ] 所有新增计算在 Rust 后端完成。
- [ ] 视觉风格无明显退化，通过 Supervisor 确认。
- [ ] 核心功能在 AI 关闭时仍完全可用。

---

## 7. 明确禁止事项

- 禁止用前端计算替代后端约束或覆盖计算。
- 禁止只实现传感器数据模型而不做三维可视化。
- 禁止环境模型只留空接口。
- 禁止 AI 功能未经后端鉴权直接调用。
- 禁止因新增功能导致 Phase 1 已有地球影像、多对象回放、报告导出等能力回退。
- 禁止擅自将 Phase 2 范围缩减后声称完成。
